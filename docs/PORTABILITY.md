# Запуск на другом компьютере

Есть три варианта: просмотр готового HTML, нативный полный пересчёт с Python, контейнер с собственным Python. Универсального запуска на любой ОС и процессоре нет: поддержка ниже ограничена конкретными платформами.

## 1. Только просмотр — без установки

Передайте `output/graph.html` и откройте в актуальном Chrome, Edge, Firefox или Safari. Данные и код встроены, сервер/интернет/Python не нужны. Для надёжного сохранения дел используйте HTTP-вариант: поведение localStorage на file:// зависит от браузера. В HTML виден результат последнего расчёта, сырые Parquet он не пересчитывает. Автоматически проверен Chrome; остальные браузеры здесь не запускались.

## 2. Полный проект — CPython 3.11

Скопируйте исходники, data/ и vendor/; **не переносите .venv между машинами**. Пакеты подбираются по ОС и архитектуре интерпретатора.

| Система | Офлайн-комплект |
|---|---|
| macOS 12+ Apple Silicon | macos-arm64-py311 |
| macOS 12+ Intel | macos-x86_64-py311 |
| Linux x86-64, glibc ≥2.17 | linux-x86_64-py311 |
| Linux ARM64, glibc ≥2.17 | linux-aarch64-py311 |
| Windows x64 | windows-amd64-py311 |

На macOS/Linux:

```bash
sh run.sh --serve
```

На Windows, из cmd или PowerShell:

```bat
.\run.bat --serve
```

Адрес: http://127.0.0.1:8765/graph.html. Запуск автоматически устанавливает закреплённые пакеты из локального каталога, пересчитывает результаты и запускает сервер. Без `--serve` создаются только выгрузки. Альтернативный порт: `--serve --port 8766`.

Единая точка входа непосредственно через Python:

```bash
python3.11 launch.py --serve
```

В Windows: `py -3.11 launch.py --serve`. Диагностика без изменений: `python3.11 launch.py --doctor`. Параметры `--data`, `--out`, `--top` предназначены для пакетного режима без `--serve`; относительные пути отсчитываются от места вызова.

Python 3.12/3.13, 32-битные ОС, native Windows ARM, Alpine/musl и Linux ARMv7 не входят в этот офлайн-комплект. При старой/перенесённой .venv переименуйте её и повторите запуск; установщик не удаляет её автоматически. Нативный сценарий фактически проверен на macOS arm64. Для остальных платформ проверены выбор комплекта и контрольные суммы; запуск на этих ОС ещё требуется.

## 3. Docker — Python внутри контейнера

Нужен установленный Docker Engine или Docker Desktop с Compose и работающим режимом Linux-контейнеров. Конфигурация рассчитана на linux/amd64 и linux/arm64, поэтому подходит также для Docker на Intel/Apple Silicon Mac и поддерживаемой конфигурации Windows. Документация Docker о [платформах](https://docs.docker.com/build/building/multi-platform/) и [Compose](https://docs.docker.com/reference/compose-file/build/).

```bash
docker compose up --build
```

Откройте http://127.0.0.1:8765/graph.html. Если старый сервер занимает порт — остановите его либо поменяйте левую часть порта в compose.yaml, например `127.0.0.1:8766:8765`.

Первой сборке нужен базовый образ `python:3.11-slim-bookworm` (его загрузка требует интернет, если он не закэширован). Python-пакеты ставятся из включённых wheel без PyPI. После сборки приложение работает без внешних API. Образ Python закреплён по ветке 3.11, но не по digest: при повторной сборке патч-версия базового образа может измениться. Для точного воспроизведения передавайте уже собранный образ.

Результаты сохраняются в именованном Docker-томе, исходные данные подключены только для чтения. Получить выгрузки на компьютер:

```bash
docker compose cp aml:/app/output ./docker-output
```

Остановить: `docker compose down` (без `-v`, чтобы оставить результаты). Служба запущена непривилегированным пользователем; в контейнер не попадают локальная .venv и история Git. Внешний доступ ограничен публикацией порта на 127.0.0.1.

### Полностью офлайн через готовый образ

На машине с Docker и интернетом соберите образ под архитектуру целевой машины, затем:

```bash
docker image save -o hackalem-aml.tar hackalem-aml:local
```

Перенесите архив, compose.yaml и папку data. На целевой машине:

```bash
docker image load -i hackalem-aml.tar
docker compose up --no-build --pull never
```

Один сохранённый одноплатформенный образ не становится универсальным для всех процессоров. Для разных архитектур готовьте отдельные образы. Сам Docker должен быть установлен заранее. **Docker здесь не установлен, поэтому реальная сборка/запуск контейнера пока не проверены.**

## Что проверено

Нативный запуск и чистая офлайн-установка macOS ARM, обработка пробелов в пути, выбор комплекта для пяти целевых платформ, отказ при неполном/повреждённом wheelhouse и передача параметров launcher. Остальные реальные ОС и Docker требуют проверки на соответствующем хосте; наличие конфигурации не выдаётся за успешный кроссплатформенный тест.
